# 时间戳溢出时 unsign() 抛出 OSError / ValueError，而不是 BadTimeSignature

复现环境：Windows + Python 3.13 + pytest

---

所有外部传入的令牌我们都会过一遍 `TimestampSigner.unsign()` / `TimedSerializer.loads()`，
并且只捕获 `BadTimeSignature` 家族——这是我们唯一的错误处理分支。

线上出现了签名和时间戳都被改过的令牌，`unsign()` 直接抛出别的异常逃过了 except：

```python
from itsdangerous import TimestampSigner

signer = TimestampSigner("secret-key")
signed = b"value.TgPVoaGhoQ.AGBfQ6G6cr07byTRt0zAdPljHOY"

signer.unsign(signed)
```

实测：

- Windows：`OSError: [Errno 22] Invalid argument`
- Linux：`ValueError: year 21959264258072993 is out of range`

时间戳字段解出来是 `21959264258072993`（约 6.9 亿年之后），把这个数字转成日期时溢出了。
但既然签名本来就不对、时间戳又根本转不出日期，这就是一个坏签名，应该和其它坏时间戳一样，
统一抛 `BadTimeSignature`，并且此时 `date_signed` 为 `None`。

约束：
- 不得靠放宽已有的 `except`（例如直接 `except Exception`）吞掉无关错误——只处理日期溢出的两种情况；
- 只改源码，不要动测试与测试配置。
